**AI短剧助手**是一款面向 Apple Silicon 的开源 Mac 短剧播放器与下载器。支持红果、西饭与河马来源的剧名搜索、选集下载和本地剧库，红果与西饭还提供分类浏览；播放进度、下载队列、视频去重与剪映草稿都在同一个桌面应用里管理。

这是社区维护的修改版本，**不是红果或西饭官方客户端，也未获平台官方背书**。Apple 公证是发行包的安全检查，不代表 App Store 审核或内容授权。

## 安装与开始使用

需要 **macOS 13 或更新版本、Apple Silicon（M 系列）Mac**。当前发行包为 arm64，应用已内置所需媒体工具，使用时无需安装 Node.js、Homebrew 或 FFmpeg。

1. 打开 [最新版本下载页](https://github.com/XASDSdsa/hongguo-drama-mac/releases/latest)。Windows 下载 `hongguo-downloader-1.1.30-Setup.exe`，免安装用同版本的 `portable.exe` 或 `win-x64.zip`。Mac 下载 `hongguo-downloader-1.1.30-mac-arm64.dmg`。解压或安装后即可使用，不需要另装 Python。
2. 打开 DMG，把「AI短剧助手」拖入「应用程序」，再从「应用程序」启动。
3. 在「设置」中选择下载目录；进入「发现短剧」选择来源，或在「搜索与下载」中查找剧名，打开详情后选择分集。

**v1.1.30 的 Mac 构建使用 ad-hoc 签名，未进行 Apple 公证。** 首次打开时请按 macOS 提示确认来源；发行页提供应用源码、FFmpeg/x264 对应源码及 DMG 的 SHA256 校验文件，方便核对下载文件。

## 从发现短剧到本地剧库

| 你要做的事 | 应用里的操作 |
|---|---|
| 找一部剧 | 按来源、分类与题材浏览海报，翻页查看目录，或直接搜索剧名。 |
| 只下载想看的集数 | 在详情中选择单集、多集或输入区间；例如 `1-10`、`1,3,5`。锁定集自动跳过。 |
| 查看下载进度和失败 | 到“管理剧集”点开这部剧：失败的集会写明原因（资源缺失、网络失败、被平台拒绝、磁盘错误等）并给出“重试”；没下载的集可以一键补下。并发数可在设置中调整。 |
| 接着上次看 | 内置播放器记录分集和播放位置，支持本地播放、在线播放与自动连播。 |
| 批量去重已下载视频 | 在“管理剧集”里点开这部剧，选集后点“开始处理”；进度、日志和失败原因都在这部剧的页面里，所有剧的总览在剧列表顶部的“总任务”。 |
| 整理磁盘空间 | 查看文件占用，删除单集或整部剧，清理转码缓存；也可扫描下载目录补登记已有文件。 |

### 先看，再决定下载

在「我的剧库」中，点击尚未下载且未锁定的分集可尝试在线播放，双击加入下载队列。开启连播后，未下载的可用分集会转为在线播放；锁定分集会跳过。

在线播放不保存到下载目录。部分片源需要先准备临时媒体文件，应用会在使用后清理。播放地址和可用清晰度由来源服务决定；遇到不兼容的媒体，可使用内置兼容转码。

播放器快捷键：`空格` 播放或暂停，`←` / `→` 后退或前进 5 秒，`↑` / `↓` 上一集或下一集，`A` 切换连播。

### 下载后，在“管理剧集”里处理

下载完成的剧会出现在“管理剧集”。点进这部剧，选要处理的集，点“开始处理”即可；多个批次共享全局 8 个处理槽位。

除下载时按剧名建一个文件夹外，目录完全由你指定，程序不会再自动建“来源/ID摘要/阶段”之类的子文件夹，也不会按目录去猜哪些文件属于哪部剧。“设置”页按用途分成四组，改完点最下面的“保存设置”才生效（没改时按钮是灰的，有改动会显示“有未保存的修改”，可以“还原”）：

- **保存位置**：下载目录（每部剧在这里建一个以剧名命名的文件夹；去重成品、剪映草稿也放在这部剧自己的文件夹里）、文件命名规则、整剧合并输出目录。
- **下载与网络**：最大并发下载数、网络代理（代理在弹窗里单独保存）。
- **去重与剪映草稿**：去重同时处理几集、草稿处理线程数、草稿生成后是否自动清理分析中间文件、剪映路径；“高级”里是拆解设备、镜头音轨、标点模型和分析中间文件目录。
- **AI 发布素材**：中转地址、Key 和模型。

字幕、分析等中间文件保存在应用自己的数据目录（高级里可改位置），不会写进你的输出目录。

### 管理剧集

“管理剧集”把一个文件夹当作一部剧：列出下载目录下的剧文件夹，也可以用“导入已有剧”选任意文件夹（只记路径，不改动、不删除里面的文件）。下载一部剧时，会顺手把来源平台的封面和简介存进剧文件夹（`封面.jpg/png/webp`、`简介.txt`），已有的文件不会被覆盖；不同来源的两部剧同名时，后来的文件夹自动加来源后缀。

剧很多时列表分页（每页 12/24/48/96 部，可输入页码跳转，也可按剧名搜索）。点开一部剧进入它自己的页面（不是弹窗）：页头是剧名，下面按文件夹中实际存在的视频列出各集（不依赖下载记录），每集只显示“第N集”，一页 30/60/100/200 集，同样可跳转页码。

没下载成功的集不再单独列出，原因直接写在那一集的标签上（**资源缺失**、**网络失败**、**已暂停**、**下载中 42%**、**没下载**），失败的、没下载的点一下标签就重试/下载。下载失败时程序会先自己换新链接重试 3 次（间隔 2、5、12 秒），链接过期、节点临时没有这集、网络抖动这类问题基本不用你动手；仍失败才标出来。**资源缺失**只在平台明确说“没有 / 未开放 / 锁定”时才显示，下载链接 404 或取不到播放地址显示的是**链接失效**/**下载失败**（都值得重试）。

**处理区在剧集下面，按「勾选要做的事」组织**：

- **先定新剧名**：成品用「AI 发布素材」里选定的新剧名命名（`新剧名_第001集.mp4`），剪映草稿名也跟着成品走；没选定剧名不能开始去重。之后再改剧名，「去重」里已有成品会自动改成新名字（有任务在跑时先不改，日志里会说明）。
- **一部剧同一时间只跑一批**：分析切点、处理中、等补下载时，「开始处理」不可点。每次重新拆分前，「去重」里的旧成品会挪进废纸篓，成品文件夹里只留最新一版。
- **视频去重**：只有一种方式，按「去重参数」里设置的每集时长（默认 30–65 秒）把选中的集接起来重新切成新的集，再去重；参数里还能改新集编号、变速、画面等。页面上直接显示「每集 30–65 秒，预计约 N 集」。
- **支线任务 · 生成剪映草稿**：分轨方式可选 **3 分轨**（文案 · 视频 · 音频各一条轨道，直接用已有的视频分镜解析切原视频，文案轨就是字幕：每条对应一个人声片段、起止与人声一致，和多分轨的字幕轨一样初始隐藏并缩放 1%，不渲染分镜文件）或 **多分轨**（把完整的视频结构化拆解走一遍：分镜、人声/背景分离、台词识别、分镜导出，再生成视频片段、文案、字幕、配音、背景声、特效声等多条轨道）。两种方式都要先做结构化分析，3 分轨只是在最后一步不渲染分镜文件、直接用分析结果切原视频。草稿不用每集都做：最多 4 集，四个格子里自由填成品集号（默认 1、2、3、4，留空的格子不做）；按去重成品文件名里的「第N集」判断（就是新集号），只用去重后的成品，成品里没有的集号会在日志里提示并跳过。勾了去重就在去重完成后接着生成（草稿正在生成时，新的几集排到后面接着做）。几集草稿会按电脑情况同时做（最多 4 集，线程预算平分给每一集）：线程不够、内存不够、正在去重或系统负载高时只做一集，做到一半电脑变忙，多开的几路会自己退出，剩下的接着一集一集做；只勾草稿则用「去重」文件夹里已有的成品，草稿放进 `剪映草稿` 文件夹或剪映草稿目录。**自动清理**（设置里可关，默认开）：每集草稿生成成功后，清掉这一集在软件数据目录里的分析中间文件（分镜片段、人声/背景声、识别结果等，一集几百 MB 到几 GB）；只删确认是结构化拆解项目的文件夹，去重成品、剪映草稿、原视频都不会动，失败的集和正在运行的项目也会保留（便于重试）；之后需要重新做草稿时会重新分析；新集编号改了，草稿默认集号会跟着一起顺延；
- 点「开始处理」，下面就是进度和日志。

**处理进度和日志都在这部剧的页面里**，不用到别处找：最下面是「处理进度」——一条总进度条（剪映草稿在生成时多一行自己的进度），下面分两个日志框：「主任务日志」按时间记着加入队列、切点分析、每集开始/完成/失败、强制拼接等；「支线任务日志」记海报/简介等发布素材和剪映草稿每一集的进展。可以停止、清空日志、打开成品文件夹。这些状态都由后台保存：切到别的页面再回来、重启应用，进度和日志都还在（正在处理的集重启后会标为已停止，可重新处理）。

> 左侧菜单里原来的「视频处理」「视频结构化拆解」「一键处理」三个页面已经移除，底层功能（去重、结构化拆解、剪映草稿流水线）都还在，统一从「管理剧集」里这部剧的页面使用。

**去重不改分辨率**：成品和原视频一样大（宽高取偶数），横屏还是横屏，不加黑边、不做模糊背景，参数里也没有分辨率选项。裁边和旋转之后会缩回原尺寸。

**重新拆分按时间线处理，开始前先预览**：处理范围只能是「整部」或「从第一集起的前 N 集」（点某一集就是处理到这一集为止），不能跳着选。页面底部会按这些集的时长和当前参数估出「预计生成约 N 集」，点「开始处理」时再弹一次预览确认（范围、预计集数、新集编号、每集时长）。真正的切法要等分析完镜头切换和说话停顿才定，所以集数可能差几集。结尾如果只剩一点点内容（不到最短时长的四分之一），会直接并进最后一集，不再强行要求它落在时长范围内。

剧列表页顶部是「总任务」：所有剧的处理中、排队、下载中、失败一眼看全，点一行进入那部剧；剧卡片上也会显示「处理中 / 下载中 / 有失败」角标。

去重只有一种方式（界面上不再区分，底层的按原集去重仍保留）：

- **重新拆分**：先裁掉每集片头片尾，再把选中的集按集号接成一条时间线，按“成品时长范围”重新切成新的集，最后逐集去重。切点优先落在镜头切换、说话停顿和原集交界处；每集的变速倍数在设定范围内取，并按成品时长倒推，所以成品时长一定落在范围里。结果放进 `剧文件夹/去重/`，命名为 `剧名_第001集.mp4`。

重新拆分会先看选中的集之间缺了哪几集，并在卡片里用虚线占位标出原因：**平台无此集**、**已锁定未解锁**（来源本来就没有，下载不了）默认直接拼接，只在结果里提示；**没下载 / 下载中 / 下载失败**（平台有、还能补）会弹窗让你选“先补下载，下完自动继续处理”或“不管，强制拼接”；**导入的文件夹**软件不知道缺的是哪种，会问一次“本来就缺，直接拼”，确认后记住。缺口处切点会优先落在两集之间。

参数面板分“时间与速度”（成品时长、片头片尾裁剪、变速范围）和“画面参数”。切点分析结果缓存在应用的数据目录里，不进你的文件夹。

### AI 发布素材（简介 / 剧名 / 海报）

在“管理剧集”里打开一部剧，顶部有“AI 发布素材”面板。**剧名、简介、海报是三件各自独立的事，各有各的按钮**，没有“一键全部生成”，一次只跑一件。**AI 改写出来的只是草稿**：内容进到编辑框并标成“未保存”，点“保存剧名 / 保存简介 / 保存样式”才写进剧文件夹；每一项旁边都标着“已保存 / 未保存 / 还没有”，可以“还原”，并单独列出“原剧名”“原简介”和“当前已保存的简介”，不会再分不清是改之前还是改之后：

1. **改写剧名**（以及改写简介，分开点）：剧名一次文本调用给出 5 个候选剧名、题材、标题样式和海报角标。候选剧名由程序按规则排序（长度、是否有钩子、不与原名雷同、不含“最”“第一”等绝对化用语），点候选或手填只是放进编辑框，点“保存剧名”才算选定（成品命名、海报都用已保存的剧名）；重新改写只更新候选，不会替换已保存的剧名。已有海报时，保存新剧名会按新名字重新排版，不再调用模型。简介单独一次调用，AI 写的新简介同样要点“保存简介”才写入 `发布简介.txt`，不动剧名和海报。
2. **生成海报**：**要先保存剧名**，没保存好（或剧名有未保存的改动）按钮点不了；标题样式、角标改了也要点“保存样式”才生效。先根据选定的剧名和简介构思画面，再用图像模型以 `封面.*` 为参考重绘（没有封面就按画面描述生成），**要求画面里不出现任何文字**，下方三分之一留空。随后让视觉模型检查画面有没有文字、人脸在哪；有字就重画（最多 3 次），模型不支持看图时跳过检查。
3. **程序排版标题**：标题不交给图像模型画（中文容易错字、位置不稳），而是用打包的字体在画布上渲染：8 套样式（鎏金霸总、烈焰逆袭、古风朱墨、冷光悬疑、糖果甜宠、血色复仇、紫金玄幻、都市硬朗），由文本模型按题材挑选。位置由程序算：把底图缩小后比较下/上/中三条候选带的画面复杂度、肤色占比和人脸重叠，选最空的；再按底图亮度铺暗角，保证对比度。

结果为 `发布剧名.txt`、`发布简介.txt`、`发布海报.jpg`。无字底图和状态放在应用私有目录，所以之后换剧名、样式、角标只是重新排版，不再调用模型。

设置页的“AI 发布素材”可填 OpenAI 兼容的中转地址和 Key；文本和作图可以各用一组（作图留空则共用文本那组）。默认文本模型 `gpt-6.1-sol`、图片模型 `gpt-image-2.5`，都可以改成中转站支持的其他模型。海报字体取自 Fontsource（OFL 1.1），构建时由 `npm run setup:title-fonts` 准备。

### FFmpeg 的准确对应源码

Windows 包使用 **FFmpeg 9.0.2-hongguo-nvenc12.2**，固定 nv-codec-headers n12.2.72.0，并保留 NVENC、AMF、QSV 和 CPU 编码器。该构建和完整对应源码包位于[固定依赖发行页](https://github.com/XASDSdsa/hongguo-drama-mac/releases/tag/ffmpeg-9.0.2-nvenc12.2)，准确 SHA256 位于 `build/ffmpeg/WINDOWS-BUILD.json`；构建脚本是 `scripts/build-ffmpeg-source-win.sh`。包内附带实际构建报告及依赖许可，静态链接依赖已包含，使用时无需安装 MSYS2。

Mac 包内置的 FFmpeg / FFprobe 基于 **FFmpeg 9.0.2** 与 **x264 `b35605ace3ddf7c1a5d67a2eb553f034aef41d55`** 的未修改源码编译。此构建为 **GPLv3-or-later**，仅静态链接 x264，保留 VideoToolbox，未启用 `nonfree`；动态依赖仅为 macOS 系统库，不依赖使用者的 Homebrew 环境。
