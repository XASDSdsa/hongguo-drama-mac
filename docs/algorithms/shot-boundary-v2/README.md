# 切镜算法 V2：切点改为"下一镜头的第一帧"

算法标识：transnetv2-temporal-min2s-v2。**待用户确认**；v1（`../shot-boundary-v1`，2026-10-14 已确认）原样冻结，不修改。

## 为什么要有 V2

TransNet V2 在硬切处标出的是**旧镜头的最后一帧**（官方训练标注 `one_hot_index = prev_end`，官方 `predictions_to_scenes` 也把该帧算作旧镜头末尾）。v1 把这一帧当作新镜头的第一帧，所以导出的每个分镜都多带了上一镜头的最后一帧。

用 App 自带检测代码和真实权重跑了合成视频（新镜头第一帧为 100、200）：模型标出 99、199；v1 的切点是 [99, 199]，V2 是 [100, 200]。端到端导出后，第 3 段第一帧与源视频第 200 帧一致，不再是第 199 帧。

## 与 v1 的差别（只有这些）

- 候选、时间结构复核（`verify.py`）、最短 2 秒动态规划（`duration_policy.py`）字节不变，复核仍以模型标出的那一帧为准。
- 输出的每个切点 = 模型帧 + 1。最短 2 秒按真实切点时间计算，切点分数取模型帧的分数。
- 标在视频最后一帧上的候选没有"下一镜头"，直接忽略。
- `decisions[].frame` 是切点帧，`decisions[].model_frame` 是模型标出的帧。

## 影响

- 同一视频的切点整体后移 1 帧，镜头数量通常不变；只有刚好卡在 2 秒边界上的镜头可能变化。
- 旧项目的分镜缓存会因算法标识变化而重新生成。内置运行时（PyInstaller 打包的 worker）需要重新构建，否则运行时自检会提示更新。
- 第 103 集的 22 段结果需要在 V2 下重新核对并确认后，才能作为新的基线。

回归检查：`python3 scripts/check-shot-boundary-convention.py`。
