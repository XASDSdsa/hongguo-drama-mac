# 视频结构化拆解：实现与验收

日期：2026-10-14。依据用户提供的《视频结构化拆解_方案选型.md》。新页面使用本地结构化处理主链；旧重建实验文件保留，但不接入本主链。

## 当前入口与范围

侧栏「视频结构化拆解」→ 选择单集视频 →「开始完整流程」。已有项目可继续；各模块可独立运行、重试、重跑。按方案先单集，本次不开发批量发布。

模块：src/native/video-structure/；页面：src/components/Reconstruction.jsx。

| 模块 | 前置 | 输出 |
|---|---|---|
| media | 视频 | media.json：真实逐帧 PTS、时长、流信息、统一起点 |
| audio | media | original_audio.wav、audio.json：44.1kHz 双声道与偏移 |
| shots | media | shots.json、predictions.json：TransNet V2 与结构复核，保留确认的视觉切点 |
| separation | audio | vocals.wav、background.wav、separation.json |
| transcript | media、separation | transcript.json、recognition.json：Paraformer＋VAD＋全局标点断句＋Whisper 声学句对齐 |
| alignment | shots、transcript | aligned.json：原视觉切点、每句完整台词及其交叠镜头索引 |
| clips | media、alignment | 最终分镜 MP4、clips.json：原声或静音，全帧保留 |
| export | alignment、clips、transcript | subtitles.srt、files.json |

业务模块不启动其他模块。单步前置不满足则阻止启动；完整流程由调度器串联。重任务执行于子进程，界面只接收节流状态事件。线程数可配置，重模型按顺序运行。

## 时间与模型规则

- 时间单位秒，原视频统一播放起点为零；镜头左闭右开，帧号从 0 开始。
- 分镜使用逐帧 PTS，不按平均 FPS 推算 VFR 边界。
- 切片重新编码，逐帧核对数量与 PTS，并验证视频末端时长。PTS-STARTPTS 避免小数除时间基造成 tick 误差；关闭 B 帧重排并显式保留末帧时长，避免 VFR 尾帧截短。
- 音频先整集提取、整集分离、整集 VAD 识别；样本时间加回音轨偏移，映射回原视频。
- 固定模型 Inst_HQ_3 预测的是背景。sherpa 1.13.8 CLI 把直接模型输出参数命名为 vocals，所以固定映射：CLI vocals → background.wav；CLI accompaniment（输入减预测）→ vocals.wav。已用实际对白验证，不能仅凭 CLI 参数名称决定轨道。
- 两轨时长按采样精度校验。分离残留与音质仍需试听，不承诺无损。
- 视觉检测结果和输出切点保留不改；完整台词、人声可连续跨镜头，不为台词合并画面。每句仅建立一条完整台词记录，并索引全部交叠镜头。
- 旧缓存只允许审核过的精确哈希对迁移：media/audio/separation 可复用不变输入；shots 仅允许结构 worker 与 runtime.json 的指定旧→新组合；speech.js 的旧→新只适用于 separation。transcript 不迁移，必须按句级标点与声学对齐参数重跑；源文件、模型、参数、前置结果、工具和输出文件仍逐项校验。
- 视频与特效声按原视觉切点输出；人声按完整识别句的说话区间输出，允许跨镜头；背景声仍保持整集。全局 SRT 每条台词只写一次，毫秒取整仅限整集起止。
- 识别、标点与声学句对齐仍需实测核验。SRT 毫秒显示不等于毫秒识别精度，也不承诺识别完整或百分百正确。

## 存储与恢复

默认目录：输入视频所在目录 / 结构化拆解 / 单集名称与摘要 / project.json。
结果目录：modules / 模块 ID / 运行 ID /。

先写 partial 临时目录，完整校验后原子改名，再标记成功。失败、停止不交接半成品；单步重试不擅自启动后续步骤。成功后清理本模块旧产物，减少重复空间占用。

输入内容、路径、模型哈希、模块代码、参数、工具、前置结果纳入指纹；续跑校验输出哈希。损坏或变化使相关下游失效，独立分支保留。处理中原视频变化会拒绝交接。应用退出时等待子进程停止，重启识别未完成状态。

## 内置运行时

- 包含 TransNet V2/PyTorch、sherpa 原生分离程序、Paraformer、Silero VAD。用户不需要 Python 或 API Key。
- 构建机运行 npm run setup:structure，可通过 STRUCTURE_BUILD_PYTHON 指定 Python 3.12。初次构建会下载固定官方模型并转换 TransNet 权重；TensorFlow 仅构建时使用，不进入应用。
- PyInstaller 独立 worker 在不含系统 Python 的 PATH 下执行真实识别与 TransNet 自检。
- npm run check:structure-bundle 验证文件哈希、自检和系统兼容性；发布前缺少有效运行时会阻止构建。
- 为 macOS 13 固定 PyTorch 2.5.1、NumPy 1.26.4。已扫描内置 Mach-O 依赖，最高最低系统版本要求为 11.1；应用自身最低仍为 13。
- sherpa 内置 CPU 多线程运行时；TransNet 显式选择 CPU/MPS，设备不可用就明确报错，不静默降级。Windows 构建脚本使用 CPU torch，未提供 CUDA 包。
- Mac/Windows 打包路径和构建工作流已接入。本次未发布应用、未上传 GitHub；Windows 尚未实机验证。
