# 完整字幕：修复与验证记录

本次仅修改字幕链路及其直接依赖：已去重视频 → 本地识别 → 词级对齐 → 时间轴校验 → 保存 SRT。没有调用付费 API，没有自动生成剧情文案，也没有改变其他开发者的下载、去重或拼接算法。

## 完成规则

- 以去重视频为输入，按画面时间起点规范化音轨；补回前导空白与音轨内部空档，裁掉画面起点前的音频，并限制到视频时长。
- faster-whisper 开启词级时间对齐，按每条字幕首词和末词定界。对白文本不按摘要删减。
- 检查全部字幕块的编号、格式、正时长、顺序、重叠和视频边界，并用音轨已知起止位置排除模型落在人工补零区内的字幕边界。无可靠时间的条目返回具体错误，不静默丢弃后仍报完成。
- 工作者仅写唯一临时目录。保存前核对输入视频版本，通过后替换正式 SRT 并记录完成状态。目录中只有每集 SRT，不增加转写 JSON/TXT。
- SRT 内容哈希、输入视频版本与识别批次版本共同约束下游。字幕损坏或去重视频变更后，旧结果不能用于新的分析；分析运行中版本改变也不能落盘覆盖。
- 各剧共用全局并发额度，包含环境探测。进度只保留在内存，批量入队一次保存。停止与退出应用均等待子进程关闭，随后释放额度并允许重试。

时钟样本使用独立已知音频位置验证：延迟 2 秒后落在 2～3 秒；视频起点 5 秒且音频起点 7 秒时仍落在视频的 2～3 秒；音频早于画面 2 秒时保留画面内的 0～1 秒。605 秒测试视频中，两段声音仍落在 301～301.25 秒和 601～601.25 秒，10 毫秒采样窗口没有测出累积位移。内部缺包空档保留在原来的位置。

另用内置模型测试真实中文语音整体延迟 2 秒：发现 VAD 留白使首字幕提前约 0.35 秒，已用音轨起点约束纠正。修正后完整文字保留，整段起点的相对误差为 0，终点约 0.01 秒。加留白后模型分句数量从 7 条变为 1 条，因此此项比较全文和整段边界，不把分句数量当作文字准确性的证明；也不据此承诺其他视频逐句达到相同误差。

真实样本为当前本地的《布衣成圣》001 集文件，探测时长 **163.033333 秒**。Mac arm64、CPU/int8、tiny 模型下，音频处理、完整识别、词级对齐和保存校验约 **2.39 秒**，输出 **62 条** SRT。该时长不是此前另一份文件的“3 分 41 秒”。内置引擎搬移到独立 Resources 目录后，在空 PATH、空模型缓存、无有效外部 Python 配置下再次识别同一整集，仍输出 62 条且通过校验。

## 验证边界

以上验证覆盖任务状态、文件版本、时间轴处理和打包运行。没有人工逐字校对整集，也没有逐句建立人工标注的起止时间，因此不能据此保证文字零错误或每句时间误差小于 0.1 秒。字幕间的静音间隔是正常现象，不能把所有字幕时长相加当作视频时长。

Windows 媒体/队列/Python 输出检查已接入 Windows 检查及发布流程；本轮未在 Windows 真机或 NVIDIA CUDA 上运行，未发布新安装包。

## 复现检查

构建机已准备项目内置 FFmpeg 后执行：

```sh
npm run check:subtitles
python scripts/check-subtitle-alignment.py
npm run check:premium
node scripts/check-download-safety.cjs
node scripts/check-renderer-lifecycle.cjs
npm run build:react
```

重新构建字幕引擎后执行 `npm run check:transcription-bundle`，再用 `scripts/check-bundled-transcription.cjs` 检查安装包的 Resources；可额外传入一个视频路径做整集离线识别。Python 仅为构建/测试工具，安装包用户无需安装。
